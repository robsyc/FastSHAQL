# ADR-0024 — Mutations via DASH construct templates

**Status:** Proposed (revised round 3; supersedes the shape-rules-first candidate)

## Context

ADR-0020 reverted a CRUD mutation surface and left a revisit lesson: writes demand staged-transaction control, not per-field validation. Round 1 investigated the SHACL 1.2 rules family (`sh:rule` shape rules, SPARQL-RL) and prior art (TopBraid, GraphDB, Ontotext: none couple shapes-as-interface with multi-node writes; prior art caps out at single-entity CRUD once relationships enter). Round 3 added the DASH template vocabulary ([templates](https://www.datashapes.org/templates.html), [multifunctions](https://datashapes.org/multifunctions.html)) and re-derived the design around it.

Spec findings that shaped the decision (vendored snapshots, `docs/references/`):

- SPARQL 1.2 Update §3.1.3: `WITH <g>` scopes the WHERE *only in the absence of* `USING` — so `WITH <write> INSERT … USING <reads> WHERE …` is a legal single-operation commit form (reads `reads`, writes `write`). Whole-request atomicity of compound requests is SHOULD-strength; per-operation atomicity (Update §4) is a MUST.
- SHACL Appendix A pre-binding (no MINUS / no VALUES on `$`-vars / no `AS ?$var`) applies identically to `sh:Parameter` pre-binding and `$this` — one rule set for any `$`-variable mechanism.
- Feasibility spike (`/tmp` → preserved in scratch): VALUES-injection pre-binding, the two-step commit, and deterministic skolemization all validated on rdflib 7.6.

## Decision

- **Templates, not rules (Era 1).** A mutation is a **Mutation template** — a DASH `dash:SPARQLConstructTemplate` (`sh:construct` + `sh:prefixes` + `sh:parameter`) published by an API view. Parameters give the GraphQL mutation input fields for free (path → `$variable`, `sh:datatype`/`sh:class` → input type, `sh:description` → description; `sh:codeIdentifier` renames the argument). Nested inputs arrive via `sh:node`-typed parameters (the process contract needs multi-node inputs); the SHACL 1.2 `sh:SPARQLRule` becomes a documented later widening (a rule is sugar: target-driven `$this` binding over a template body).
- **Commands, not records.** The unit of mutation is the template, not the shape. TopBraid-style CRUD may join as a second surface by v1.0.
- **Lowering, not pre-binding.** fastshaql injects a namespaced `VALUES` clause (parameters, emulated `$this`) into the WHERE at lowering time — one mechanism across all stores; Appendix-A restrictions constrain only *author-written* bodies. Optional parameters lower to `UNDEF` (unbound terms drop out of CONSTRUCT results — the correct semantic). Injection must namespace its variables: a collision with an author variable silently captures it.
- **Two-step execution.** Dry-run = execute the lowered CONSTRUCT (read scope via the existing `FROM`/`read_graphs` machinery) → skolemize → return the triples. Commit = the same, then a single `INSERT DATA { GRAPH <write_graph> … }` — per-operation atomic (Update §4), no reliance on compound-request atomicity. The skolemizer must sit between read and write (bnodes materialize with store-chosen labels inside a single-op update), which is why the single-op `WITH…USING…INSERT…WHERE` form is only the recorded engine alternative (also: rdflib requires a `Dataset` and `SPARQL_LOAD_GRAPHS=False` for `USING`). The read-then-write window is a documented engine contract.
- **Deterministic Skolem IRIs.** Constructed blank nodes become `sha256(mutation IRI + sorted parameter bindings + bnode-normalized describing triples)` IRIs at the fastshaql boundary: same template + same input ⇒ same IRIs, so dry-run ≡ commit and reruns converge (idempotent by input; duplicate-minting guards belong to the author, per author-owns-correctness). Bnode labels must be normalized out of the hash (raw labels are nondeterministic — spike-verified). Structurally symmetric distinct bnodes collapse — accepted limitation. The skolemizer is an internal seam; a call-unique strategy is one adapter away. Author-minted IRIs (`IRI(CONCAT(… ENCODE_FOR_URI($label)))`) remain the encouraged path.
- **Typed triples payload.** `{ triples: [Triple!]!, tripleCount: Int! }` with term-typed scalars — a **named deviation from prior art** (TopBraid: `Boolean` + `_MutationReport` + commit-by-omission; GraphDB/Semantic-Objects: entity selection + `affected_count`; Hasura: `affected_rows`/`returning`): none can express the process contract's multi-node result, which has no single affected-row type. The payload type is shared with the future CONSTRUCT-export read surface (query-type consolidation). Serialized RDF (Turtle/N-Triples as a `@specifiedBy` string scalar) is an adapter/HTTP-layer concern, not a schema concept; an in-query `format` argument has no prior art and is rejected for now.
- **Scoping arguments.** Mutation fields take `readGraphs`, `writeGraph`, `dryRun` (absent write graph ⇒ dry run). The adapter's `context_getter`/`ResolverContext` may constrain or override both — server declarations beat client requests (the ADR-0008 lesson). One `writeGraph` per operation; multi-graph writes by authoring explicit `GRAPH` blocks in the template body. `QueryContext.write_graph` keeps its reserved semantics (ADR-0011); the mutation seam is its first consumer.
- **Closed-by-default, view-declared visibility.** Mutation templates are inert until an API view (`graphql:Schema` today) publishes them (public/protected/private grammar extended, e.g. `graphql:publicMutation`). The vocabulary is worded transport-agnostically so a future **declared** MCP view — possibly read-only alongside a read-write GraphQL view — reuses it. Derived (strip-mutations-in-code) MCP projections are rejected for the same reason as ADR-0008: governance must be declared, not hidden.
- **Translator, not engine.** fastshaql compiles templates to SPARQL; the store executes; fastshaql processes results. No fixpoint iteration, no in-library conformance checking, no background materialization. The author owns correctness; guards live in the template's WHERE clause.
- **Phased by dependency.** 0a: `ConstructQuery` + update AST forms over `GroupPattern` (feeds CONSTRUCT-export too). 0b: store widening — `query_construct` (triples decode) + `update` on `SparqlStore`; `InMemoryStore` via rdflib `Dataset.update()`. 0c: resolver-kwargs passthrough in `executable.py` (fixes the `$variables` backlog item at the same seam). 1: mutation-template parser arm (`core/ir/` frozen union + `core/parser/` module mirroring `node_expr/`), VALUES-injection lowering, dry-run execution, typed payload, visibility wiring. 2: skolemizer + commit. The E2E harness extension (`run_mutation_case`: `mutation.graphql` + `variables.json` + `expected.sparql` + `expected.triples.json` + optional `data.expected.ttl` isomorphism-checked post-state) rides Phase 1; the first ticket of each slice is a failing fixture (ADR-0021).
