# ADR-0027 — Polymorphic filters: the where-shape, member-keyed predicates, and quantifiers

**Status:** Proposed (design settled 2026-09-28; ships with the polymorphic-filters slice, then flips Active)

## Context

ADR-0026's boundaries reject filters on polymorphic fields until this design: member-keyed inputs and the type-discrimination operator ("only Employees" is a `where` concern — inline fragments select fields, never members). The `where`-shape question was entangled with the ROADMAP *More filters* open decision (additive sibling fields vs. breaking wrapper) — resolved here, once, for both, by survey (2026-09-28): named quantifiers converge on a `{some, every, none}` wrapper input (PostGraphile's connection-filter on to-many relations; Prisma on all relations); the bare object consistently means exists/some where it ships (Hasura on both relation kinds, PostGraphile on to-one); no surveyed library ships quantifiers as suffixed sibling fields, and none ever migrated a shipped bare-object field into a wrapper post-launch (Prisma's bare→`is`/`isNot` displacement is the friction exhibit). The ROADMAP's "Hasura/PostGraphile convention" premise is corrected: Hasura is flat — its users express every/none via `_not` double negation (exactly this library's designed lowering) and have asked for explicit quantifiers for years; that path is tolerated, not loved. PostGraphile's cardinality split — bare object on to-one (exists-and-match), wrapper on to-many (where quantification means anything) — is the closest precedent, and `sh:maxCount 1` gives fastshaql the same signal. Union type-discrimination inside `where` is near-novel: Weaviate's class-name-as-path-segment and Strapi's REST-only `__component` pseudo-key are the only structural precedents; GraphQL-level support is otherwise absent (Strapi documents it unsupported).

## Decision

**Where-shape: cardinality split.** A to-one relationship (`sh:maxCount 1`) keeps the bare filter object — exists-and-match, a missing value fails — unchanged for monomorphic fields and native for polymorphic ones; one value quantifies nothing. A to-many relationship carries a wrapper input `{Parent}{Field}Filter` with three optional quantifier fields `some`/`every`/`none` that AND-combine. The monomorphic to-many migration (today's bare object → wrapper) is decided here and executes with the More-filters wave — pre-1.0 is the cheap moment; the additive-sibling alternative has zero precedent and would preserve exactly the shape whose missing quantifiers Hasura's users regret.

**Member-keyed predicate.** Inside (or, on to-one, *as*) the filter sits one member-keyed input `{Parent}{Field}Match`: one field per member, keyed by the member's discriminator name (the member type name; the binding class for a binding union — one model for both forms), each holding that member's `{TypeName}Filter`, plus the **type-discrimination operator** `type` (`eq`/`neq`/`in`/`notIn` over a per-field member-discriminator enum). The keys form one **disjunctive predicate** P(x) = typeOp(x) ∧ ⋁<sub>keys</sub>(is-a Mₖ ∧ conditionsₖ) — requiring different members independently composes at the parent level (`AND` of separate filters), never inside the predicate. A key matches by **class-guard is-a** (subclass-closed `rdf:type/rdfs:subClassOf*`), independent of member-order priority, which governs only `__typename` stamping at selection.

**Quantifiers are strict.** `some` = ∃x P(x) (`FILTER EXISTS`); `none` = ¬∃x P(x); `every` = ¬∃x ¬P(x) — double negation, **vacuously true on an empty value set**, documented rather than silently redefined (Prisma-compatible). The predicate ranges over all values, not per-member subsets — `every: {Paragraph: {}}` is "only Paragraphs" (childless passes); tolerant readings ("every Paragraph child matches, others ignored") compose from negated operators inside `none`. Degenerate spellings: `some: {}` is exists-any, `every: {}` a no-op, `none: {}` cardinality-zero. Null values and empty objects no-op exactly as monomorphic relationship filters; `{Paragraph: {}}` is the is-a-Paragraph predicate.

**Names are taken-sets.** Wrapper and Match names allocate against every synthesized type name (numeric suffix on collision, the ADR-0006 precedent). Member keys colliding with reserved names (`some`/`every`/`none`, `type`, `AND`/`OR`/`NOT`, `iri`) reject loudly at schema build — the remedy is `sh:codeIdentifier`. No combinators inside the Match; the parent's combinators already compose whole wrapper values.

**Lowering.** Each quantifier is one EXISTS over the same pieces a selection lane uses — link emission, `VALUES` membership guard, SHACL-instance lane guard, member conditions — with `none`/`every` wrapping in `!(EXISTS { … })` (the renderer's negation form); filtered polymorphic fields promote exactly like monomorphic ones, and nested scopes take fresh `_rf_` variables (ADR-0009). Derived sources keep the ADR-0026 containment unchanged. Implementation detail, revisitable like all lowering.

## Consequences

- ADR-0026's filter boundary lifts when slice 3 implements this; its three backstop messages re-point here
- The ROADMAP *More filters* open decision is resolved — its `every`/`none` operators take the wrapper shape fixed here; scalar `exists`/`isNull` and case-insensitive patterns are unaffected
- The `polymorphic_filters/` E2E set (12 cases, spec in the handoff) locks the semantics: the dual-typed overlap row pins class-guard is-a against stamping priority; the childless row pins vacuous truth
- Interfaces (a future derivation from node-shape inheritance, ADR-0005) reuse the member-keyed predicate unchanged — any member-set-bearing field filters the same way
- Three new input types per polymorphic to-many field (wrapper, Match, discriminator enum) enter the schema surface and the taken-set
